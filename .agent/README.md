# Архитектура Независимых Агентов LegalEstate
*Реорганизовано: 2026-10-30*

Этот проект переведён с модели монолитного файла на **систему независимых модульных агентов**. Каждый агент имеет изолированную зону ответственности, свои правила и инструменты.

## Карта агентов

| Агент | Файл профиля | Специализация | Инструменты / Зона работы |
|---|---|---|---|
| ⚖️ **Legal Agent** | `.agent/agents/legal_agent.md` | Подготовка ДКП, ПДКП, ДС, передаточных актов, расписок, законы РФ (152-ФЗ, 127-ФЗ, 255-ФЗ, ГК РФ). | `python-docx`, шаблоны `templates/`, папки `deals/` |
| 📐 **Layout Agent** | `.agent/agents/layout_agent.md` | Верстка Word (.docx), Правило 10 (подписанты во всю ширину), ровно 1 страница А4, 0 мягких переносов (`\n`). | Word COM Automation, `win32com`, аудит разрывов |
| 🛡️ **Security Agent** | `.agent/agents/security_agent.md` | Проверки контрагентов по базам МВД, ФНС, ФССП, Федресурс, суды, ведение `MASTER_LOG.xlsx`. | Модуль `intern_workflow.py`, Playwright, шлюзы госорганов |
| 🔄 **Sync Agent** | `.agent/agents/sync_agent.md` | Синхронизация между устройствами (`git pull/push`), автофиксация в 17:55, порядок в папках. | Git, системный scheduler, крон-задачи |

## Главное правило взаимодействия с пользователем (Zero Overhead Policy)
1. Пользователь ставит бизнес-задачу обычным языком («сделай акт», «проверь человека», «подготовь допник»).
2. Ведущий агент самостоятельно определяет затык, подбирает нужного агента и нужный инструмент, не нагружая пользователя техническими вопросами.
3. Перед выдачей любого документа проводится автоматическая сверка по 3 точкам (Юрист -> Верстальщик -> Проверка файла в Word).
4. Если возникает повторяющаяся проблема — ведущий агент **проактивно предлагает пользователю сформировать нового специализированного агента** с готовыми правилами и инструментами.
